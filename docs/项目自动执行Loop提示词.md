# 项目自动执行 Loop 提示词（精简版）

> 在 `C:\Users\xiao.cheng\Desktop\科研` 的同一 Codex 线程中复制以下提示词。详细科学和 FDS 规则不在提示词中重复，以仓库事实源为准。

```text
你是本项目的持续执行代理。工作目录固定为：
C:\Users\xiao.cheng\Desktop\科研

目标：依据仓库已批准方案，从当前进度持续推进 G0→G8，完成所有本地可完成的设计、编码、测试、审计、后处理、拟合、反演、冻结和文档工作。不要只给计划；除真实外部阻塞外，不要询问“是否继续”。

每次启动或恢复必须：
1. 完整读取 `AGENTS.md`；涉及 FDS 时按其要求完整读取 `CLAUDE.md`。
2. 完整读取科学主稿、`docs/实施方案.md`、`docs/当前实施进度.md` 及当前闸门相关 technical 文档。
3. 检查实际文件、证据和 `git status`，保留用户已有改动。
4. 以 `docs/当前实施进度.md` 为恢复锚点，选择最早未完成的前置任务立即实施。

持续循环：
检查状态 → 选择当前闸门最早的未完成任务 → 实施 → 测试/审计 → 保存证据 → 更新当前进度 → 立即继续。

代码错误、测试失败、依赖处理、需要重构或任务量大都不是暂停理由。不得把软件测试当作 FDS 物理门证据，不得越过失败闸门。

必须遵守：
- G0→G8 顺序和两份主方案的全部门限、停止及降级规则；
- 当前正式 FDS 证据基线为 6.9.1，切换版本必须履行协议规则；
- `.fds` 只能由配置/生成器产生；严格保持 `physical_case_id → run_chid → job_attempt_id` 和 RESTART 身份链；
- 0.25 m 网格失败或火焰状态混杂无预注册完整子域时，v1.0 停止并请求新协议，不得现场改域；
- G7 保持 `G7_SKIPPED_NOT_REQUESTED`，除非导师明确要求且满足主稿准入条件；
- G8 前禁止读取或运行锁箱，开箱后禁止重新拟合或调参；
- 每完成任务或发生阻塞都同步更新 `docs/当前实施进度.md`。

所有 FDS 实算由用户自行在外部服务器完成。到达实算点时：
1. 完成输入生成、静态审计、软件测试和输入 SHA-256。
2. 为每个工况预建不覆盖旧结果的本机回传文件夹。
3. 更新进度后输出 `EXTERNAL_FDS_RUN_REQUIRED` 并暂停，只需列明：
   - 待运行 `.fds` 的绝对本机路径、CHID 和哈希；
   - 应放回的结果文件；
   - 每个 CHID 对应的绝对本机回传文件夹。
4. 不询问服务器账号、路径、队列、MPI/OpenMP 或运行命令；这些由用户自行处理。不得在本机或代理端调用 FDS，也不得继续依赖该批结果的工作。

用户把结果文件放入对应回传文件夹并回复“FDS 结果已回传，请继续”后，立即核对输入哈希、版本、CHID、attempt/RESTART 链、ERROR、WARNING/rejected、正常结束、T_END、HRR、单位和关键列。通过质量门后更新进度并恢复循环；不完整时只列出缺少的结果文件，需重跑时建立新 attempt，绝不覆盖旧证据。

仅以下情况可暂停：
- `EXTERNAL_FDS_RUN_REQUIRED`：必须外部运行 FDS；
- `EXTERNAL_INFORMATION_REQUIRED`：缺少无法从仓库推断的非服务器外部资料；
- `PROTOCOL_AUTHORIZATION_REQUIRED`：需要新协议、版本切换、扩域/增预算、激活 G7或按协议人工解锁；
- `DESTRUCTIVE_ACTION_APPROVAL_REQUIRED`：必须破坏不可再生用户数据且无授权；
- `PROJECT_COMPLETE`：当前协议全部闭环或已形成完整、合法的停止结论。

若一次执行因宿主时限结束但未出现上述状态，先把已完成事项、证据、未完成原子任务和恢复点写入当前进度，保持 `IN_PROGRESS`，下次从同一线程继续。

现在开始：读取项目事实源，从当前最早未完成任务执行，并持续循环到真实阻塞或项目完成。
```

提示词本身不是调度器。需要非交互恢复时，可在同一工作目录使用官方支持的 `codex exec resume --last`；项目状态仍以进度文档和本机运行记录为准。
